# English Vocabulary Database v0.2 Design

## 1. Background

The v0.1 prototype established a simple Excel-based vocabulary list for computer science students. Its six terms and three-column layout are retained as the seed data for v0.2.

### Polished v0.1 specification

The original purpose was to create a searchable and reviewable vocabulary database for technical English. Excel was selected as the storage format. Each record contained a number, a word, and an English meaning. The prototype included six test terms and was intentionally small enough to validate the layout before adding more vocabulary.

## 2. Problems identified in v0.1

- The meaning column was too narrow, so longer definitions were clipped in the default view.
- The three-field schema did not support pronunciation-free study context such as part of speech, example usage, topic, or source traceability.
- The workbook had almost no visual hierarchy: headers and body cells used the same plain style.
- The table did not expose filtering or keep its header visible during scrolling.
- Two blank worksheets were included even though the prototype had only one active data area.

## 3. v0.2 requirements

1. Keep the six v0.1 terms and add no more than fifteen new terms.
2. Select the new terms from page 1 of the supplied glossary document.
3. Expand the header row with fields that support lookup and study.
4. Improve readability with a restrained color system, wrapped text, wider columns, and consistent alignment.
5. Make the records sortable and filterable and keep the header visible while scrolling.
6. Record the source of each term so that future additions remain traceable.
7. Deliver the workbook and this English design document in `version control/v0.2`.

## 4. v0.2 data model

The active worksheet is `Vocabulary` and contains 18 records: the 6 v0.1 terms plus 12 terms from page 1 of the supplied glossary.

| Field | Purpose |
| --- | --- |
| `No.` | Stable sequential record number. |
| `Word` | The technical English term. |
| `Part of Speech` | A compact grammatical label such as noun, verb, adjective, or operator. |
| `Meaning` | A concise English definition. |
| `Example Sentence` | A short programming-focused usage example. |
| `Topic` | A study category such as Operators, Strings, or Functions. |
| `Source` | The v0.1 seed list or the supplied glossary page reference. |

The 12 new terms are `addition`, `alias`, `argument`, `associativity`, `backslash`, `binary`, `bit`, `bitwiseAND`, `bitwiseNOT`, `bitwiseOR`, `bitwiseXOR`, and `Booleanoperator`.

## 5. Visual and usability design

- Use a dark navy header with white text for strong contrast.
- Use a pale blue body band for the new glossary records and a neutral tint for the v0.1 seed records.
- Use a light amber fill in the `Source` column to make newly sourced terms easy to identify.
- Wrap definitions and examples, with fixed column widths and row heights that keep text readable.
- Freeze the first four rows and the record-number column.
- Use an Excel table named `VocabularyTable` with filter buttons for quick lookup.
- Keep the workbook focused on one active `Vocabulary` worksheet instead of carrying forward unused blank sheets.

## 6. Scope boundaries

The release is a curated vocabulary list. It does not add audio, pronunciation, automated quizzes, spaced repetition, or external database synchronization. Those features can be considered in a later version after the data model has been reviewed.

## 7. Acceptance criteria

- The workbook opens as `version control/v0.2/v0.2.xlsx`.
- The active table contains 18 records and seven labeled fields.
- No new glossary terms exceed the fifteen-term limit.
- Definitions and examples are visible without relying on the formula bar.
- The workbook can be filtered by word, topic, or source.
